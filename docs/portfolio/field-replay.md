# 一线任务回放与验收记录

状态：待执行。当前没有真实参与者、观察结果或用时记录。空表仅为收集工具，不是调研成果。

## 任务和方法

先选择一个高频任务：汽车方向“整理客户询价信息并准备一次合规跟进”；智能服务方向“课程咨询缺知识时整理上下文并交给人工”。确认可脱敏样本与参与者后再记录。

建议小规模探索从2—3名业务人员、每人3—5个同类任务开始；人数是计划，不是实际参与。先记录现有方法，再以相同难度但不同内容任务体验原型，轮换顺序减少学习影响。包含失败、放弃和修改，不能只挑成功例。该规模只用于发现可用性问题，不做因果增长结论。

## 每条必须记录

匿名参与者ID、角色、日期、脱敏任务ID、业务类型、人工/辅助顺序、原输入、开始时间、查资料分钟、处理分钟、复核分钟、补采返工分钟、建议采用/修改/驳回/放弃、修改内容、完成结果、接收方是否仍需重问、错误类型和说明。

总人工分钟=准备+处理+复核+补采返工；任务完成需有业务认可的结果，只有生成或送达不算完成。任务未完成的时间照样计入。所有分母保留开始的任务，不剔除超时。

## 验收前对齐

- 业务：定义有效承接/已解决、应停止的联络、风险问题边界。
- 产品：范围、基线、样本、事件定义、接受/修改/驳回与回退路径。
- 算法/研发：模型/Prompt/知识版本、结构化校验、工具回执、失败日志及权限。
- 数据/运营：观察窗口、去重、成本项及任务与线索关联。

发现无依据价格承诺、拒联后动作或错误写入即暂停自动执行并保留样本；演示环境只观察建议，由人工决定下一步。
