# 观望意向分流规则对照

这组验证只回答“同一购车咨询输入，规则修改后怎样分类和建议下一步”。它是本次作品集新增的模拟规则比较，不是历史生产复测，也没有调用真实模型或执行联系。

## 复跑

Python 3.10 及以上，无第三方依赖。在本目录运行：

```bash
python3 -m unittest -v
python3 run.py
```

输出 `raw-results.json`、`逐例结果.csv` 与 `summary.json`。参照、规则、样例校验值见 `freeze-manifest.json`；修改被冻结文件会使运行停止。新版本应另建目录，不覆盖本次记录。

## 样本与比较约束

- 数据集 `hesitation-routing-v1`：D01—D12 为12条开发样例，F01—F24为24条合成冻结检查样例。规则先完成开发断言，再保存冻结文件，首次运行后未依据冻结结果调规则。
- 规则和参照均由AI助手整理，未获业务双人标注；冻结仅保证版本可复核，不能称独立盲测或真实客户泛化测试。
- `failure_baseline` 刻意复现“负向词或RAG缺答案即拒绝”的简化失败模式，不是原公司旧系统；`revised_rule` 将客户意向与知识状态分开。两者共用建议路由器。
- 每条保存全部客户轮次、知识状态、参照、输出、原话轮次、失败字段和本机规则函数CPU毫秒。输出仅建议，均需人工确认，不创建回访、不发消息。
- 现有C01—C08未执行方案样例、DriveFollow 8个规则场景、DriveReach 40例卖车规则集、地址24例均为不同数据集，未计入本次分母。

## 本次结果

开发集完整字段一致：5/12 → 12/12。冻结检查集：9/24 → 18/24。这里的完整字段指意向、电话拒联、建议路径三项与参照均一致。

冻结集16条咨询参照中，被判拒绝12/16 → 1/16。4条电话拒联参照中，两组均漏识别1/4；改进规则仍有6条失败：F16—F21。K01同一咨询在4种知识状态下，修订规则意向一致，回答路径随知识变化。

失败包括否定范围、跨轮省略、同义表达及非标准拒联。尤其F20未识别拒联，不能进入自动执行；不存在“所有风险都拦住”的结论。规则输出带证据文本，不代表证据推理正确。

## 真实模型与业务验证

真实模型比较未执行，API费用与模型延迟为未测，不填0冒充测量。当前外部API调用数为0，规则CPU计时不代表端到端服务延迟；未包含开发、标注、复核成本。

后续使用相同输入、相同建议路由器，要求模型只输出 `intent`（consulting/declined/unknown）、`phone`（denied/unknown）、`all_stop`、`evidence_turn` 与 `evidence_text`；校验枚举、证据确实来自对应轮次、禁止新增购买事实。格式失败单独计入，不删除。每条保存供应商、模型快照、Prompt版本、原始响应、解析错误、耗时、token用量及实际价格表。

为避免用已见失败调参后冒充验收，应将本集用于后续开发，再征集脱敏新整通、由业务双人标注并仲裁，冻结独立验收批次。比较咨询漏判、误升高优、拒联动作、无依据价格回答、任务完成及净人工分钟。本规则实验未生成价格答案、未预测高优、未真实执行，不能据此报告这些指标。
